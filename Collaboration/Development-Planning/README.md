# Development Planning

팀 프로젝트를 진행하며 반복해서 발생했던 **구조와 협업 기준의 차이를 줄이기 위해 만든 소규모 팀 프로젝트용 개발 계획서 템플릿**입니다.

처음에는 기능 범위, 역할 분담, 프로젝트 구조, API·DB 설계, Git 협업 규칙처럼  
**팀원끼리 구현 기준을 맞추는 것**을 중심으로 만들었습니다.

이후 실제 팀 프로젝트에 적용하고 AI Agent를 학습하면서,  
AI 프로젝트에서는 **AI가 어디까지 판단할 수 있는지와 Tool을 어떤 기준으로 사용할지** 역시 설계 단계에서 정할 필요가 있다고 느껴 템플릿을 확장했습니다.

## 📄 Template

- [소규모 팀 프로젝트 개발 계획서](./PLAN_TEMPLATE.md)

### 현재 포함된 주요 설계 영역

- 프로젝트 목표와 MVP
- 기능별 완료 기준
- 팀원 역할과 협업 범위
- 기술 스택과 시스템 구조
- 화면·API·데이터 설계
- Git / Branch / PR 규칙
- 설치·환경변수
- 테스트와 예외 처리
- 발표·제출 기준
- **AI / LLM / Agent 설계 `[AI 프로젝트 선택]`**
  - LLM / Tool / Agent 필요성 판단
  - Agent 역할과 자율성 범위
  - Tool 사용 조건
  - 정보 부족·모호한 요청 처리
  - Structured Output / Validation
  - AI 실패 상황과 테스트 기준

> 모든 프로젝트에서 AI 항목을 사용하는 것은 아닙니다.  
> 일반 프로젝트에서는 해당 부분을 삭제하고, AI가 필요한 프로젝트에서만 선택적으로 사용합니다.

## 🔄 템플릿 개선 기록

- ### 초기 버전

팀 프로젝트에서 경험한 문제를 바탕으로  
**AI와 함께 개발하더라도 사람이 먼저 구현 기준과 협업 기준을 명확하게 정하는 것**에 집중했습니다.

- ### AI Agent 학습 후

Tool Calling과 Agent를 학습하면서  
**서비스 안에서 AI가 판단하고 행동할 때 필요한 기준**을 추가했습니다.

현재는 범용 템플릿을 유지하면서 AI 프로젝트에서만 사용할 수 있도록  
`AI / LLM / Agent 설계`를 선택 항목으로 제공합니다.

RAG, Memory, Multi-Agent 등은 미리 항목을 만들지 않고,  
앞으로 실제로 학습하고 프로젝트에 적용하면서 설계 단계에서 필요성을 확인한 내용만 추가할 예정입니다.
