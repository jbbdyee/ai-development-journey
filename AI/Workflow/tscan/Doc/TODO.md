## 만들고 싶은 것

개발자나 보안 담당자가 어느 폴더에서나 `tscan` 명령을 실행해 지정한 폴더나 git 커밋 직전(staged) 파일에서 노출된 API 키, `.env` 값, 주민등록번호·전화번호·이메일 등 비밀과 개인정보를 찾아 **안전하게 가린(마스킹된) 채로** 보여 주는 터미널 도구(CLI 및 Textual TUI)를 만든다.

pre-commit 훅으로 자동 실행되어 비밀이 저장소에 커밋되는 사고를 사전에 차단하고, 배포 파이프라인이나 다른 프로그램이 연계할 수 있는 JSON 출력과 명확한 종료 코드를 제공한다.

## 요청에 없지만 걱정되는 것 (숨은 요구의 씨앗)

- **결과 객체 오염 방지:** 결과 데이터 클래스나 딕셔너리에 `raw_value` 필드를 남겨두면 향후 디버깅 출력이나 로그 포맷팅 시 실수로 유출될 위험이 있다. 탐지 즉시 마스킹하고 원래 값은 메모리에서 즉시 폐기해야 한다.
- **`.env` 메모리 보안:** `.env`에서 추출한 비밀값은 비교 목적으로만 메모리 세트에 보관하고 파일이나 로그, 예외 스택트레이스에 노출되지 않도록 철저히 격리해야 한다. 너무 짧은 값(예: 6자 미만 또는 `true`, `123`)까지 비교하면 모든 파일에서 오탐이 폭발하므로 최소 길이 기준이 필요하다.
- **Staged 검사의 정확성:** 작업 트리의 파일 내용(`cat <file>`)이 아니라 git 인덱스에 실제 스테이징된 내용(`git show :<path>`)을 읽어야 `git add` 후 로컬에서 수정한 내용과의 혼선이 없다.
- **바이너리 및 대용량 파일 처리:** 이미지, zip, 컴파일된 바이너리(NUL 바이트 포함)나 1MB 이상의 대용량 파일을 정규식으로 읽으면 성능 저하 및 메모리 초과가 발생하므로 사전 필터링이 필수적이다.
- **TUI 비동기 응답성:** 수천 개의 파일을 스캔할 때 TUI 메인 스레드가 블로킹되면 화면이 멈추므로, 스캔 엔진은 백그라운드 Worker 스레드에서 돌고 결과를 점진적으로 UI에 전달해야 한다.
- **Hook 안전성:** 기존 개발자가 Husky, pre-commit 프레임워크 등을 쓰고 있을 경우 덮어쓰면 협업 환경이 깨진다. tscan 전용 시그니처 주석을 확인하고 안전하게 공존하거나 중복 설치를 거부해야 한다.
- **테스트 격리:** 테스트 파일 안에 하드코딩된 가짜 키가 있으면 `tscan`이 자기 자신의 테스트 코드를 검사할 때 걸린다. pytest 픽스처(`tmp_path`) 내에서 문자열 조각(`"sk-" + "test-" + ...`)을 동적으로 결합해 임시 파일로 생성해야 한다.
