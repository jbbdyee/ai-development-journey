# tbench 구현 계획

기준 문서: `Doc/TODO.md`, `Doc/SPEC.md`. 체크는 구현과 확인이 모두 끝난 뒤에만 표시한다. 2026-10-26 검증 결과는 문서 끝에 기록했다.

## 엔진 1단계 · 요청, 측정, 통계 (R1·R6·R7·R8)

- [x] `pyproject.toml`과 `tbench` 명령 진입점을 만들고 URL·`--body-file`·`-n`·`--timeout`·반복 `--header`·`--warmup`·`--plain`을 받는다.
- [x] JSON 본문을 보내고 응답 본문을 끝까지 받은 뒤 한 호출의 번호·HTTP 상태·경과 시간·실패 종류를 돌려준다. 결과는 호출이 끝날 때마다 소비할 수 있게 한다.
- [x] 연결 실패, 시간 초과, 4xx, 5xx를 분류한다. 실패 호출은 횟수와 실패 수에 포함하고 성공 시간 통계에서는 제외한다.
- [x] 성공 시간의 nearest-rank p50·p95·max, 실패 종류별 수, 첫 호출 제외 p50을 계산한다. 첫 측정 행은 `first call`로 표시한다.
- [x] 예비 호출은 측정 전에 수행하되 지정한 N개 결과와 통계에 섞지 않는다.
- [x] 인증·키 머리글을 출력하거나 이후 저장할 데이터에 넣을 때 `***`로 가리는 공통 함수를 만든다.
- [x] pytest의 로컬 가짜 서버로 정상·지연·첫 호출 지연·4xx·5xx·연결 거부·시간 초과를 확인한다. 1~10초 자료의 p50=5초·p95=10초를 테스트로 고정한다.

확인: `uv run pytest -q`; `uv run tbench http://127.0.0.1:<가짜서버포트>/ --body-file <시험용.json> -n 5 --plain`. 실제 헬프데스크는 자동 테스트에 사용하지 않는다.

## 엔진 2단계 · 저장과 비교 (R3)

- [x] `--save <파일>`로 실행별 JSON을 남긴다. 시작 시각·URL·메서드·본문 SHA-256·N·동시 수·warmup·timeout·가린 머리글·개별 결과·요약을 포함한다.
- [x] `tbench compare <before.json> <after.json>`에서 p50·p95·max·실패 수의 전후 값과 변화율을 표로 보여 준다. 0 또는 값 없음일 때 변화율 표현을 정한다.
- [x] URL·본문 해시·N이 다르면 비교 결과에 경고를 표시한다. 원문 본문과 비밀 머리글이 파일에 없는지 확인한다.
- [x] 저장 형식과 비교 계산을 가짜 결과 파일로 테스트한다.

확인: `uv run pytest -q`; `uv run tbench compare before.json after.json`; 시험용 키를 사용한 저장 파일에서 그 키 원문을 검색해 결과가 없는지 확인.

## TUI 1단계 · 실시간 결과 (R2)

확인: `uv run pytest -q`; `uv run tbench http://127.0.0.1:<지연서버포트>/ -n 5`를 실행해 진행 중 화면을 직접 확인.

## 엔진 3단계 검증 기록 · 2026-10-26

- R4: 최대 k개 worker로 요청을 실행하고 결과는 완료 순서로 받되 요청 번호를 보존한다. k=1은 기존 순차 경로를 유지한다. pytest 지연 가짜 서버에서 n=6의 최대 동시 처리 수가 k=1에서 1, k=3에서 3이었고 동시 실행이 더 빨랐다. TUI에서도 번호가 순서 밖으로 완료되는 결과 3개와 완료 요약을 확인했다.
- R10: `--max-p95`·`--max-failures` 기준을 검사한다. 성공 0건에 기준이 하나라도 있으면 `FAIL`/1, 기준이 없으면 기존 종료 동작을 유지한다. 이 정책을 `Doc/SPEC.md`에 명시했다.
- 첫 전체 pytest 실행은 12 passed, 1 failed였다. 실패 원인은 테스트가 서버의 첫 도착 요청을 엔진의 번호 1로 가정한 것이었다. 번호 1의 완료를 의도적으로 늦추도록 테스트를 수정했다. 최종 `UV_CACHE_DIR=.uv-cache uv run pytest -q`: **13 passed in 10.49s**. 기존 9개도 통과했다.
- 프로젝트 밖 임시 폴더의 editable 설치본에서 0.7초 지연 로컬 가짜 서버에 n=6으로 실행한 실제 시간: k=1 **4.35초**(p95 0.709초), k=3 **1.52초**(p95 0.710초). 두 경우 모두 실패 0건이다. k=3 결과는 완료 순서가 2·1·3·4·6·5여도 각 요청 번호를 보존했다.
- 같은 설치본에서 `--max-p95 2 --max-failures 0`은 `PASS`/종료 코드 0, `--max-p95 0.1 --max-failures 0`은 `FAIL`/종료 코드 1이었다. 실제 n8n·OpenAI API는 호출하지 않았다.

## TUI 스파크라인 점검 · 2026-10-26

- `src/tbench/tui.py`는 호출 시간이 도착할 때마다 최대 시간을 기준으로 `▁`~`█` 8단계로 표시한다. 앞서 쓴 0.7초 고정 지연 서버처럼 값이 거의 같으면 모두 `█`가 되어 흰 막대처럼 보인다. 렌더링이나 갱신 오류는 확인되지 않아 제품 코드는 수정하지 않았다.
- 가짜 서버 응답 지연을 순서대로 약 0.05·0.2·0.4초로 바꾼 TUI 회귀 테스트에서 세 가지 높이의 문자가 나타났다. `UV_CACHE_DIR=.uv-cache uv run pytest -q`: **14 passed in 11.91s**.
- 72일차 수업 폴더의 `reference/lab02-example2-cache.json`, `my-work/helpdesk.json`, `requests/faq-vpn-nocache.json`을 확인했다. 요청 본문에 `no_cache: true`가 있어 같은 본문으로 전후 측정하면 캐시를 사용하지 않는다.
- 당시 게시된 n8n 워크플로우와 로컬 `my-work/helpdesk.json`은 서로 달랐다. 실제 변경 전에 게시본을 n8n에서 내보내 별도로 보관해야 정확히 복구할 수 있다.
- 비교용 실제 웹훅은 호출하지 않았고 워크플로우도 변경하지 않았다. `flow.py push`는 같은 웹훅을 쓰는 기존 워크플로우를 게시 해제하고 n8n을 재시작하므로 전후 실행 조건과 복구본을 사용자 실행 전에 확인해야 한다.

## TUI 2단계 검증 기록 · 2026-10-26

- `--pick-request`가 TUI 시작 전에 `requests/*.json`을 나열하고 선택한 원본 JSON 바이트를 POST로 보낸다. `--body-file`과 동시 지정하거나 `--plain`과 함께 쓰면 거부한다. 빈 목록, 잘못된 JSON, 선택 뒤 누락 파일을 화면에서 처리한다.
- h 기록 화면은 기본 결과를 최신순으로 표시하고, 선택한 행을 비교 기준으로 넘긴다. c 비교 화면은 기존 `engine.compare`를 사용해 p50·p95·max·실패 수와 변화율 및 URL·본문 해시·N 차이 경고를 표시한다. 손상 기록은 목록에서 제외하고 목록 표시 뒤 파일이 삭제되면 오류를 화면에 표시한다.
- 새 Textual·가짜 서버 테스트 5개를 더해 `uv run pytest -q`: **27 passed in 19.66s**. 기존 22개도 통과했다. 기록 화면을 연 동안 worker가 결과 표를 계속 갱신하는 것도 확인했다. 80열 화면에서 날짜와 URL이 오른쪽 지표를 가리는 문제를 확인해 열을 줄이고 전체 URL을 별도 줄에 표시했으며 화면 렌더링 테스트로 확인했다. 테스트와 직접 실행에서 실제 n8n·OpenAI API는 호출하지 않았다.
- 프로젝트 밖 임시 폴더에서 전역 editable `tbench`의 요청 선택 TUI를 실제로 실행했다. 선택한 `{"question":"stage2-fake"}`가 승인된 로컬 가짜 서버에 2회 도착했고, 결과 2행·단계 평균을 확인했다. 기본 저장 후 두 번째 기록을 만들어 h 화면의 최신순 목록과 비교 화면의 네 지표·변화율·N 경고를 직접 확인했다. 샌드박스의 포트 바인딩 및 HOME 쓰기 제한으로 이 직접 실행은 승인된 환경과 임시 HOME을 사용했다.
- 66일차 수업 문서는 `turl` 기록의 필드와 저장 위치 예시를 설명하지만 `~/vibe/turl` 및 실제 `~/.local/share/turl/history.json` 파일은 없다. 실제 저장 형식과 자동 호환은 검증할 수 없어 위 항목을 미완료로 남겼다. Body JSON을 `requests/*.json`으로 별도 저장하는 수동 변환 방법을 문서화했다.

## 공개 전 점검 · 2026-10-27

- R1~R14의 필수 경로를 SPEC·테스트·구현과 다시 대조했다. `turl` 자동 호환은 실제 저장 파일을 확인할 수 없어 선택적 미검증 항목으로 유지한다.
