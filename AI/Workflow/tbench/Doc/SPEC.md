# tbench SPEC

| --- | --- | --- | --- | --- |
| R1 | URL과 JSON 본문 파일을 받아 N회 호출한다. 매회 상태·소요 시간을, 마지막에 p50·p95·max·실패 수를 출력한다. `--plain` 출력도 제공한다. | ① | `tbench <url> --body-file x.json -n 10 --plain`에서 10개 행과 요약을 확인한다. 가짜 서버가 3번째마다 500을 주면 6회 중 실패 2건이다. | 꼭 |

| R7 | 연결 실패·시간 초과·HTTP 4xx·HTTP 5xx를 각각 센다. | ⑦ | 닫힌 포트, 제한 시간보다 느린 서버, 404·500 응답으로 `connect`, `timeout`, `http_4xx`, `http_5xx`를 확인한다. | 꼭 |
| R8 | `--header "K: V"`를 여러 번 받으며 저장 결과와 호출별 로그에서는 `Authorization` 및 키 성격의 머리글 값을 `***`로 가린다. | 끝 부탁 | 시험용 키를 넣어 실행·저장·기록한 뒤 파일에서 원문 키가 검색되지 않는지 확인한다. | 꼭 |
| R9 | 응답 JSON의 `timings` 값이 있으면 단계별 평균 밀리초를 표시한다. | ⑧ | `classify_ms`, `data_ms`, `answer_ms`, `review_ms`, `total_ms`가 있는 응답과 없는 응답을 각각 확인한다. | 나중 |
| R10 | `--max-p95`와 `--max-failures` 기준을 검사해 `PASS` 또는 `FAIL`과 종료 코드 0 또는 1을 낸다. | ⑨ | 기준 안팎과 성공 0건의 가짜 응답으로 출력과 `echo $?`를 확인한다. | 나중 |
| R11 | `--log runs.jsonl`은 측정 호출마다 시각·번호·상태·시간·실패 종류를 한 JSON 줄로 남긴다. | ⑩ | N회 측정 후 줄 수가 N인지, 각 줄이 JSON인지 확인한다. | 나중 |
| R12 | `profile save <이름> <url> --body-file ...`로 설정을 저장하고 `run <이름>`으로 실행한다. | ⑪ | 다른 작업 폴더에서 저장한 이름으로 같은 요청을 실행한다. | 나중 |
| R13 | `history`는 저장된 실행의 날짜·URL·N·p50·p95·실패 수를 최신순으로 보여 준다. | ⑫ | 두 번 저장한 뒤 두 행이 최신순인지 확인한다. | 나중 |
| R14 | `uv tool install` 후 어느 작업 폴더에서나 `tbench` 명령을 쓴다. | 첫 문단 | 설치 후 `/tmp`에서 `tbench --help`를 실행하고 `uv tool list`를 확인한다. | 꼭 |

## 2. 숨은 요구와 공통 규칙

- **측정 범위:** 요청을 보내기 직전부터 응답 본문을 모두 받을 때까지의 경과 시간을 잰다. 연결 오류와 시간 초과도 시도 횟수와 실패 수에 포함하되 성공 응답 시간 통계에서는 제외한다. 실패 건의 경과 시간은 개별 행에 남긴다.
- **백분위:** 성공한 측정 시간의 오름차순에서 nearest-rank를 사용한다. 인덱스는 `ceil(p × 개수)`이며 1~10초 자료에서 p50은 5초, p95는 10초다. 성공이 0개면 p50·p95·max는 값 없음으로 표시한다.
- **기본값:** 동시 수 1, 제한 시간 30초, 예비 호출 0회. N·동시 수는 양의 정수, 예비 호출은 0 이상의 정수로 검증한다.
- **동시 실행:** 측정 요청마다 고유 번호를 실행 시작 전에 부여한다. 출력과 저장 결과는 완료 순서로 받을 수 있으므로 번호가 오름차순이라고 가정하지 않는다. 첫 호출 제외 p50은 완료 순서가 아니라 번호 1을 제외한다. warmup은 측정 전에 순차 실행한다.
- **기준 판정:** 기준 옵션 중 하나라도 지정되면 두 기준 모두 충족할 때만 `PASS`다. 성공 응답이 0건이면 p95를 계산할 수 없으므로 지정된 기준의 종류와 관계없이 `FAIL`(종료 코드 1)로 판정한다. 기준 옵션이 없으면 기존 종료 동작을 유지한다. 기준값은 0 이상의 유한한 수로 제한한다.
- **저장 메타데이터:** 시작 시각, URL, HTTP 메서드, 본문 SHA-256 해시, 측정 횟수, 동시 수, 예비 호출 수, 제한 시간과 안전하게 가린 머리글을 포함한다. 본문 원문과 인증값은 결과 파일에 쓰지 않는다.
- **저장 위치:** 명시한 출력 경로를 우선한다. 기본 결과·설정 위치는 `~/.tbench/` 아래로 통일해 현재 작업 폴더에 좌우되지 않게 한다.
- **단계별 시간:** 성공 응답의 `timings`에서 유한한 숫자형 `*_ms`만 수집한다. 단계별 누락값은 해당 단계의 평균 모수에서 제외하고 비숫자·불리언·NaN은 무시한다. 유효한 값이 없으면 `--plain`과 TUI 모두 단계별 평균 줄을 숨긴다.
- **호출별 기록:** `--log <경로>`는 측정된 호출이 완료될 때마다 JSONL을 추가한다. warmup은 기록하지 않는다. 각 줄은 시각·요청 번호·상태·초 단위 시간·실패 종류만 담고 머리글과 본문은 담지 않는다.
- **프로필:** `~/.tbench/profiles.json`에 이름, URL, 본문 파일의 절대 경로, N·timeout·warmup·동시 수를 저장한다. 본문 원문과 머리글은 저장하지 않는다. URL의 사용자 정보·쿼리·fragment는 인증값 노출을 막기 위해 프로필 저장에서 거부한다. 비밀 머리글은 `tbench run <이름> --header "K: V"`로 실행할 때만 전달한다. 저장한 본문 파일이 이동·삭제되면 실행 전에 오류를 낸다.
- **기본 결과와 기록 목록:** `--save`가 없으면 완료된 실행을 `~/.tbench/runs/`에 자동 저장한다. `--save`로 지정한 별도 파일은 기본 기록 목록에 넣지 않는다. `history`는 기본 폴더의 유효한 결과만 시작 시각 최신순으로 보여 주고 손상 파일은 건너뛴다.
- **응답성과 구조:** 호출·통계·저장 엔진은 화면과 분리하고 결과를 하나씩 전달할 수 있어야 한다. TUI는 별도 worker에서 호출을 진행해 입력과 화면 갱신이 멈추지 않게 한다. `--plain`, `compare`, `history`는 TUI가 없어도 작동한다.
- **안전한 테스트:** pytest는 자체 가짜 HTTP 서버에서 지연·첫 호출 지연·상태 오류·연결 실패를 재현한다. 실제 헬프데스크 또는 유료 API를 호출하지 않는다.
- **설치:** `pyproject.toml`에 `[project.scripts]`의 `tbench` 진입점을 정의한다.

## 3. 범위 밖

이미지 그래프 저장, 웹 화면, 여러 URL 동시 측정, 수천 회 규모 부하 시험, 결과의 서버 전송은 이 프로젝트 범위에 넣지 않는다.

## 4. 단계와 확인 원칙

먼저 R1·R6·R7·R8 엔진과 `--plain`을 확인하고, R3 저장·비교, R2 TUI, R14 설치를 순서대로 확인한다. 나중 항목도 최종 요구에서 제외하지 않고 후속 구현 계획에 남긴다. 각 구현 단계는 가짜 서버 테스트와 실제 CLI 실행으로 확인한다.

## 5. VIBE-Q와 비교

- TODO에서 첫 문단의 설치 요구와 마지막 두 부탁을 ①~⑫와 별도 항목으로 뽑았다. VIBE-Q의 R14·R8 및 가짜 서버 시험 요구와 일치한다.
- VIBE-Q의 14개 요구를 모두 포함했다. 추가로 실패 시간을 개별 행에 남기되 성공 응답의 백분위에서는 빼는 계산 규칙을 명시했다.
- **TUI 요청 선택:** `--pick-request`는 TUI 실행 전에 `--requests-dir`(기본값: 현재 작업 폴더의 `requests`) 바로 아래 `*.json` 목록을 연다. Enter로 고른 파일을 JSON으로 파싱한 후 원본 바이트를 POST 본문으로 사용하며 `Content-Type: application/json`을 기본 적용한다. 빈 목록 또는 손상된 JSON은 호출하지 않고 화면에 알린다. 기존 `--body-file`은 즉시 측정하는 명시적 본문 경로로 유지하며 `--pick-request`와 함께 쓰거나 `--plain`과 함께 쓰면 오류로 거부한다. 선택 화면에서 Esc를 누르면 측정 없이 돌아가고 q로 종료한다.
- **TUI 기록·비교:** 측정 화면의 h는 기본 폴더 `~/.tbench/runs/`의 유효한 결과를 시작 시각 최신순으로 보여 준다. 기록 행에서 Enter를 누르면 그 결과를 비교 기준으로 가져온다. 측정 화면의 c도 비교 화면을 직접 연다. 비교 화면에서 기준과 비교 대상을 고르면 CLI `compare`와 같은 p50·p95·max·실패 수 및 변화율과 URL·본문 해시·N 차이 경고를 보여 준다. 빈 기록은 안내하고, 손상 파일은 목록에서 건너뛰며 선택 후 파일이 없어지거나 손상되어도 오류를 화면에 남긴다. Esc로 이전 화면에 돌아간다. 기본 기록 폴더 밖의 `--save` 파일은 TUI 목록에 넣지 않는다.
- **66일차 `turl` 제한:** 수업 문서 `VIBE-A-TURL.md`는 기록 예시를 `~/.local/share/turl/history.json`에 메서드·URL·헤더·Body·상태·시각을 담는 형태로 설명한다. 현재 `~/vibe/turl` 프로젝트와 실제 `history.json` 파일은 존재하지 않아 실제 저장 스키마를 검증할 수 없다. 따라서 자동 가져오기는 지원하지 않는다. `turl`에서 요청 Body의 JSON만 확인해 별도 `requests/<이름>.json` 파일로 저장하면 선택할 수 있다. 기록 전체와 마스킹된 헤더를 그대로 본문 파일로 쓰지 않는다.
